Introduction

This system provides a robust framework for building extensible applications. The architecture is designed around core principles of modularity, type safety, and developer ergonomics.

Key Features

  • Plugin-based architecture with runtime discovery
  • Type-safe API with comprehensive error handling
  • Built-in logging and diagnostics
  • Cross-platform compatibility

Installation

Install the package using your preferred package manager:

Requirements

  • Delphi 10 Seattle or later
  • JCL (Jedi Code Library) 2.8+
  • JVCL (Jedi Visual Component Library) 3.0+
uses
  System.SysUtils,
  pluginapi,
  ArcanumSCRLib;

begin
  // Initialize the plugin system
  ScanForPlugins('plugins\*.dll', MainMenu, PluginsMenu, OnPluginExecute);
end;

Quick Start

Get started with a minimal working example:

program MyApp;

uses
  Vcl.Forms,
  MainForm in 'MainForm.pas' {Form1};

begin
  Application.Initialize;
  Application.CreateForm(TForm1, Form1);
  Application.Run;
end.

Configuration

Configuration is handled through INI files. The following settings are available:

Setting Type Default Description
AutoRemapLineNumbers Boolean True Automatically remaps line numbers after edits
VerboseDebug Boolean False Enables verbose debug output
RemapLineNumbers Boolean True Remaps script line numbers on compile

API Reference

Plugin Registration

Plugins are discovered automatically from the plugin directory. Each plugin must export the following functions:

// Required exports
function GetPluginName: PChar; stdcall;
function GetPluginDescription: PChar; stdcall;
function GetInterfaceVersion: PChar; stdcall;

// Optional exports
procedure RunPlugin(BasePath: PChar); stdcall;
procedure PluginConfig(BasePath: PChar); stdcall;
procedure GenerateSpeech(Male, Female, Voice, Output: PChar; Line: Integer); stdcall;
⚠️ Important
All exported functions must use the stdcall calling convention. Failure to do so will result in crashes or undefined behavior.

Error Handling

The API uses consistent error reporting patterns:

// User-facing errors - always show dialog
messagedlg('Failed to load plugin: ' + Filename, mtError, [mbOK], 0);

// Diagnostic messages - debug only
ConsoleDebug('Setting application handle for plugin.');

// Warnings - user-visible but non-blocking
messagedlg('Plugin already running!', mtWarning, [mbOK], 0);

Plugin Development

Create a new plugin by implementing the required interface:

library MyPlugin;

uses
  SysUtils,
  Classes;

{$R *.res}

function GetPluginName: PChar; stdcall;
begin
  Result := 'My Awesome Plugin';
end;

function GetPluginDescription: PChar; stdcall;
begin
  Result := 'Does something useful';
end;

function GetInterfaceVersion: PChar; stdcall;
begin
  Result := '1.0';
end;

procedure RunPlugin(BasePath: PChar); stdcall;
begin
  // Plugin logic here
end;

exports
  GetPluginName,
  GetPluginDescription,
  GetInterfaceVersion,
  RunPlugin;

begin
end.

Troubleshooting

Common Issues

Plugin not loading

Ensure the plugin exports all required functions and uses the correct calling convention. Check the debug log for specific error messages.

Crash on startup

Verify that all dependencies (JCL, JVCL) are properly installed and accessible. The crash log will indicate missing units.

🚨 Critical
Never modify files in the __history or __recovery directories. These contain backup data and recovery metadata.
